# Architecture

Turing teaches a small AI model to write and answer the way you do. It reads everything you have written, your notes and your project docs, and trains the model on that until it picks up your voice and knows your work. The result is called Samantha, and you talk to her from the terminal.

The whole thing runs on this Mac. Nothing is uploaded, no rented graphics cards, no bill. It is a small enough model to train at home, nudged toward your writing rather than rebuilt from scratch, which is why it fits.

## How it runs

First `prep_data.py` gathers your wiki and project documentation and cuts it into training examples, holding some back to check the results against. Then the training step runs on the Mac's own chip. It does not make a new copy of the model; it saves only the adjustments, a few megabytes rather than gigabytes. `parse_log.py` turns the training log into `web/status.json` so you can watch it improve.

Once she is trained, `ask.py` and `chat.py` handle questions. Before answering, they look up the relevant passages from your notes through the brain project, so answers come from what you actually wrote instead of being made up. Common questions are matched even when worded differently, and anything that changes with time, like who currently holds an office, is looked up live rather than remembered. `serve.py` runs the prompt you type into.

| File | What it owns |
|---|---|
| `training/prep_data.py` | Data pipeline. Walks Obsidian wiki + Code directory, chunks markdown into train/valid JSONL. Skips non-documentation. |
| `train.py` (via `mlx_lm lora`) | Training orchestration. Launches LoRA fine-tune on the frozen base model (Qwen2.5-0.5B). Stores weights in `ada-1-adapter/`. |
| `training/parse_log.py` | Post-training: parses loss history from `train.log`, writes `web/status.json` for the landing page. |
| `ask_faq.py` | The project FAQ, split out of ask.py: FAQ.md parsed into pairs, the lexical matcher hardened against false positives (foreign words, shared-word rarity), the optional embedding matcher, and the exact-fact extractors. ask.py re-exports every name. |
| `ask_web.py` | The web lookups, split out of ask.py: a cached JSON fetcher (FETCH_FAILED marks a dead request, distinct from no result), the live officeholder lookup on Wikidata, the local reader that answers from one article, and the guards that decline a title coincidence. `fetch_text` is the one page reader: any http(s) URL, tags stripped to plain text, or None when the page is down, blocked, or too thin to be real content (a JS-only shell), shared by `tools.read_page` and `tools_research.sources`. ask.py keeps general_knowledge and re-exports every name. |
| `ask_local.py` | Answers computed on this machine with no network, split out of ask.py: arithmetic (AST whitelist), the clock, unit conversion, small talk and the live ability list. ask.py re-exports every name. |
| `ask.py` + `chat.py` | Inference. Loads the trained adapter, retrieves facts from brain RAG, generates answers. `chat.py` wraps it in an interactive loop that keeps her model loaded and prints her words as she writes them (`generate` streams through mlx_lm and stops at echoed scaffold), and hands every command ("set the volume to 30", "take a note buy milk") to `harness.py` first, which shows the tool call and asks before anything that writes. |
| `serve.py` | CLI server. Local REPL for chat sessions. |
| `gate.sh` | Validation suite. Runs fast checks (chat, actions, parity, pixelmator, tools) against eval baselines. `release.sh` runs the full gate. |
| `stats.py` | Generates documentation coverage metrics (docstring + file citation percentages) into web/stats.json. |
| `worker.js` | Cloudflare Worker for the /api endpoints (`/api/ask`, `/api/pick`, `/api/draw`, `/api/chat`). Deploys the landing page assets via `wrangler deploy`. `/api/chat` is Ollama-compatible: `{model, messages, stream}` in, `{model, message: {role, content}, done}` out, byte for byte what Joshua Tree's kernel (`kernel/chat.h`'s `chat_send`) sends and parses. It answers small talk, then the Joshua Tree knowledge pack (`readJtDocs`, sharing `readGrounded` with the Wikipedia reader), then the same pipeline `/api/ask` uses; the origin allow-list also accepts `joshuatree.heyitsmejosh.com` and no `Origin` header at all. |
| `gen_jt_docs.py` | Builds `web/jt_docs.js` from the joshuatree repo (a sibling checkout, read-only): README, WHITEPAPER, ARCHITECTURE's app tables and roadmap, plus `kernel/kernel.c`'s own `GUI_LABELS`/`GUI_DOCK_DEFAULT` arrays for the real app list and dock order. | `tools.py` | The small fixed set of things Samantha can actually do on this Mac. Simple commands are matched by pattern and run straight away, with no model involved. Multi-step asks go to Ollama. | `tools_files.py` | Her file tools. | `tools_research.py` | Deep research: "research X" reads the top Wikipedia articles, her library, your notes, and a page named right in the question (a URL, or a bare domain, fetched with `ask_web.fetch_text` and cited as its own source), hands the relevant passages to the biggest local model, and returns a four to six sentence brief with a [n] after each claim plus the sources it used.
