# Architecture

Turing teaches a small AI model to write and answer the way you do. It reads everything you have written, your notes and your project docs, and trains the model on that until it picks up your voice and knows your work. The result is called Samantha, and you talk to her from the terminal.

The whole thing runs on this Mac. Nothing is uploaded, no rented graphics cards, no bill. It is a small enough model to train at home, nudged toward your writing rather than rebuilt from scratch, which is why it fits.

## How it runs

First `prep_data.py` gathers your wiki and project documentation and cuts it into training examples, holding some back to check the results against. Then the training step runs on the Mac's own chip. It does not make a new copy of the model; it saves only the adjustments, a few megabytes rather than gigabytes. `parse_log.py` turns the training log into `web/status.json` so you can watch it improve.

Once she is trained, `ask.py` and `chat.py` handle questions. Before answering, they look up the relevant passages from your notes through the brain project, so answers come from what you actually wrote instead of being made up. Common questions are matched even when worded differently, and anything that changes with time, like who currently holds an office, is looked up live rather than remembered. `serve.py` runs the prompt you type into.

| File | What it owns |
|---|---|
| `prep_data.py` | Data pipeline. Walks Obsidian wiki + Code directory, chunks markdown into train/valid JSONL. Skips non-documentation. |
| `train.py` (via `mlx_lm lora`) | Training orchestration. Launches LoRA fine-tune on the frozen base model (Qwen2.5-0.5B). Stores weights in `ada-1-adapter/`. |
| `parse_log.py` | Post-training: parses loss history from `train.log`, writes `web/status.json` for the landing page. |
| `ask_faq.py` | The project FAQ, split out of ask.py: FAQ.md parsed into pairs, the lexical matcher hardened against false positives (foreign words, shared-word rarity), the optional embedding matcher, and the exact-fact extractors. ask.py re-exports every name. |
| `ask_web.py` | The web lookups, split out of ask.py: a cached JSON fetcher (FETCH_FAILED marks a dead request, distinct from no result), the live officeholder lookup on Wikidata, the local reader that answers from one article, and the guards that decline a title coincidence. ask.py keeps general_knowledge and re-exports every name. |
| `ask_local.py` | Answers computed on this machine with no network, split out of ask.py: arithmetic (AST whitelist), the clock, unit conversion, small talk and the live ability list. ask.py re-exports every name. |
| `ask.py` + `chat.py` | Inference. Loads the trained adapter, retrieves facts from brain RAG, generates answers. `chat.py` wraps it in an interactive loop that keeps her model loaded and prints her words as she writes them (`generate` streams through mlx_lm and stops at echoed scaffold), and hands every command ("set the volume to 30", "take a note buy milk") to `harness.py` first, which shows the tool call and asks before anything that writes. |
| `serve.py` | CLI server. Local REPL for chat sessions. |
| `gate.sh` | Validation suite. Runs fast checks (chat, actions, parity, pixelmator, tools) against eval baselines. `release.sh` runs the full gate. |
| `stats.py` | Generates documentation coverage metrics (docstring + file citation percentages) into web/stats.json. |
| `worker.js` | Cloudflare Worker for the /api endpoints. Deploys the landing page assets via `wrangler deploy`. |
| `tools.py` | The small fixed set of things Samantha can actually do on this Mac. Simple commands are matched by pattern and run straight away, with no model involved. Multi-step asks go to Ollama. Includes `paint_image` for the painting hands. |
| `tools_logo.py` | The logo designer and painter, split out of tools.py: palettes, the golden spiral, complex and simple layouts (always an icon, never text), make_logo and paint_image, plus layers_to_svg (any of her designs as an SVG, no Pixelmator) icon_svg (Turing's icon, her flower bloom, byte for byte), icon_measures and icon_blueprint_svg (the measured construction sheet in docs/icon-blueprint.svg). Reads tools._run when called, so tests that patch it still stub these; tools.py re-exports every name. |
| `tools_agent.py` | Her hands' choices: `pick()` is her own 0.5B tool picker (hands-adapter), `_faq_knows()` keeps questions her FAQ answers away from the picker and agent, and `agent()` lets a local model drive her tools one call at a time, answering only after a tool ran. Split out of tools.py, which re-exports all of it |
| `tools_screen_agent.py` | Multi-step screen jobs ("log me into X"): a local model plans clicks, typed text and key presses one step at a time. Only click_text, type_text, press_key and see_screen are ever in its toolset, never the general model_tools() list, and every step, even a look at the screen, is confirmed before it runs. A no ends the whole job |
| `tools_research.py` | Deep research: "research X" reads the top Wikipedia articles, her library and your notes, hands the relevant passages to the biggest local model, and returns a four to six sentence brief with a [n] after each claim plus the sources it used. Sentences without a real citation, or with a number no source contains, are dropped. `save_research` writes the last brief to a file in the home folder ("save that", "save it to ~/Desktop/x.md"), asking first |
| `tools_write.py` | Write real files: "draft an email about X", "write a doc about X" hands the request straight to the biggest local model and saves what it drafts as a markdown file in the home folder, asking first, same shape as new_note. "note" stays with new_note on purpose, this is for longer drafted content |
| `tools_see.py` | Her eyes: see_screen and see_image hand a screenshot or a picture in the home folder to a local vision model (Qwen2.5-VL 3B on MLX via mlx-vlm, loaded once and kept) with your question. Private, so both ask first and stay off model menus and MCP. Reading the screen's text stays with read_screen (Vision OCR) |
| `tools_gui.py` | Her hands on the screen: click_text reads the screen with Vision OCR (ocr.swift --boxes gives each line's position) and clicks the words you named with cliclick; type_text types into whatever has focus; press_key presses one named key. All three are writes, so the harness asks before every step |
| `tools_llm.py` | ask_llm: a hard question handed to another LLM on this Mac. Name one ("ask qwen", "ask llama3.1", "ask gemma") and it is found on oMLX or Ollama; "ask claude", "ask gpt" or "ask an llm" means the biggest (oMLX Qwen3.5-9B, then Ollama qwen3:8b). A model that is not here gets the list of what is. Nothing leaves the Mac, no key. Only by name, asks first, hidden from models and MCP, every answer names its model |
| `voice.py` | Voice in: sox records until you stop talking, Whisper large-v3-turbo on MLX turns it into text on this Mac, and each turn goes through the harness and the answer chain like typing, then she says the answer. Silence and Whisper's phantom "Thank you." are skipped, "goodbye" stops. `python3 chat.py --voice` |
| `library.py` | Her offline library: the fieldbook plus the lead of all ~10,000 of Wikipedia's vital articles, in a SQLite full-text index at ~/.samantha/library. `general_knowledge` falls back to it when the web has nothing or is down. Only a page named exactly what was asked answers ("what is kinship", "who was Margaret Mead"); word matching across pages was cut after it answered wrong. `python3 library.py fetch` fills it |
| `distill.py` | Distillation: picks real passages from the project and fleet docs (no worktrees, 12 a repo), a frontier teacher writes grounded Q/A for each, every pair is checked (short, plain, grounded, a standalone question, a whole-sentence answer) and read by the local 9B as a judge (`distill.py judge`: does the answer answer the question?), wrapped in chat.build_prompt with three passages, plus declines over passages that do not hold the answer. A tenth is held out; `distill.py eval` scores her on it before and after training |
| `tools_image.py` | Image processing tools that drive Pixelmator Pro. Ten tools: remove_background, upscale_image, enhance_image, grayscale_image, rotate_image, flip_image, resize_image, crop_square, convert_image, image_info. All validate paths with `_inside_home()`, export to ~/Desktop, never modify originals. `ROUTES` makes each one an exact command ("make ~/Desktop/cat.png black and white"), no model needed, ported to `web/samantha.js`. |
| `util_math.py` | The pure utilities, split out of tools_util.py: calculate (AST whitelist, no eval of strings), convert_units, dice, coins, random numbers, passwords, uuids, hashes, base64, word count, reverse, shout, morse, json, primes, roman numerals, tips. No app, no network, no side effects. tools_util.py re-exports every name. |
| `util_dates.py` | Time and dates, split out of tools_util.py: time_in, convert_time (a time in one zone to another: cities, PST/EST/GMT/JST and IANA names, daylight time handled), current_date, days_until, and date_math (exact arithmetic from year 1 to 9999, dates spelled by hand so macOS and Linux agree). tools_util.py re-exports every name. |
| `tools_util.py` | Forty-nine utility tools that need no app: calculate, convert_units, time_in, convert_time, current_date, days_until, date_math (exact date arithmetic: N days/weeks/months/years from, after, before or ago, the weekday of any date, days between two dates, years 1 to 9999), flip_coin, roll_dice, random_number, make_password, make_uuid, hash_text, base64_encode, base64_decode, word_count, reverse_text, shout, morse_code, json_pretty, is_prime, roman_numeral, tip, plus the Mac readers disk_space, uptime, memory_usage, cpu_load, ip_address, wifi_name, system_info and the three that act, copy_to_clipboard, sleep_display, reveal_in_finder, list_shortcuts, run_shortcut the MCP client pair list_mcp_tools and call_mcp_tool, the Chrome tab tools list_tabs, switch_tab, close_tab and read_tab, memory across sessions with remember, recall and forget (a JSON file in ~/.samantha, private: hidden from models and MCP, remember and forget ask first), read_document, find_in_document and ask_document (a grounded answer from a local reader model, every number and name checked against the text), ask_screen (the same over the screen's OCR text, private and ask-first), and read_document/find_in_document (PDF through pdf.swift and PDFKit, Word, RTF and HTML through textutil, plain text, home folder only), read_screen (macOS Vision OCR through ocr.swift on a fresh screenshot, private and ask-first), and close_tab asks first and is never a model's choice (run_shortcut and call_mcp_tool only when named, never chosen by a model; call_mcp_tool asks first). Fixed argv only, silent under SAMANTHA_HEADLESS. Its ROUTES table is appended to the router in tools.py. |
| `mcp_server.py` | Her tools over MCP, so other assistants can use her hands. A stdio JSON-RPC server, standard library only: initialize, tools/list, tools/call. It leaves out the tools that fire a side effect (run_shortcut, copy_to_clipboard, sleep_display) until the harness can ask first. |
| `ocr.swift` | Reads the text in an image with macOS Vision, one line per recognized line. tools_util.read_screen runs it on a fresh screenshot. |
| `pdf.swift` | Prints the text of a PDF with macOS PDFKit. tools_util.read_document runs it for .pdf files. |
| `scratch-picker/train.py` and `scratch-picker/eval.py` | The from-scratch picker experiment: a character transformer with tool, argument-mode and span heads, and the scorer that reports the same numbers as eval/hands.py. Results and why it does not generalize are in docs/BAKEOFF.md. |
| `harness.py` | The conversation around her hands. It remembers every turn's command, tool calls and result, prints each tool call before it runs, and asks before anything in tools.WRITES (a note, a reminder, a file on the Desktop, a Shortcut, the clipboard). tools.plan() finds the calls without running them. |
| `pixelmator/pxm_spec.py` | pxm's trust boundary, split out of pxm.py: exit codes, the shape and key tables, PxmError, colour and string parsing, and validate_spec, which every spec passes before any AppleScript is written. Pure, no Mac needed; pxm.py re-exports every name. |
| `pixelmator/pxm.py` | Painter logic. Repaints a photo using quadtree algorithm (split most-wrong region into four cells). Drives Pixelmator Pro via AppleScript. Handles layer creation, coloring, and bounds checking. |
| `pixelmator/arc_text.py` | Text-along-arc rendering for logo design (used by `make_logo` tool). |
| `menubar/PaintBar.swift` | SwiftUI menu bar app. Lets you pick a photo, shows live painting progress, has a background switch to hide Pixelmator. Supports `--paint <image>` for headless QA. |
| `menubar/build.sh` | Build script for PaintBar. Creates the macOS app bundle. |
| `gen_hands_data.py` | Generates training data for the hands (tool picker). Harvests labeled examples for action classification. |
| `harvest_voice.py` | Voice data harvester. Collects training examples from git commits (183 pairs extracted from fleet repos), used for style transfer beyond documentation alone. |
| `run_lora_capped.py` | Utility to run LoRA training with memory caps, protecting against OOM crashes on the 16GB machine. |
| `train_resilient.sh` | Wrapper script for resilient training runs (retries on crash, memory limits). |
| `release.sh` | Cut a release: run checks, bump VERSION, tag, push, publish GitHub release, deploy site. |
| `.github/workflows/deploy.yml` | The landing page deploys itself: after the test workflow passes on main (or by hand), `wrangler deploy` ships worker.js and web/, then it waits until the live page serves the version in VERSION. Needs the CLOUDFLARE_API_TOKEN repo secret; without it the run is skipped green with a notice, never a red main. |
| `.github/workflows/release.yml` | Releases cut themselves: when the test workflow passes on a push to main whose VERSION has no tag yet, it tags that commit and publishes the GitHub release. No Mac gate, no deploy: those run with `release.sh` on the Mac. |
| `test_nimble.py` | Integration tests for Nimble service integration (via serve.py REPL). |
| `eval/hands.py` | Automated QA for tool picking and action execution. Measures precision of wrong picks and false refusals. |
| `eval/score.py` + `test_chat.py` | Automated QA over a held-out test set. No eyeballed results, CI validates every run. |
| `test_tools_image.py` | Unit tests for image tools. Mocks Pixelmator's pxm module so tests run on Linux CI without the app. Tests path validation, argument parsing, AppleScript generation, and output file handling. |
| `test_mcp.py` | A real client conversation against mcp_server.py: initialize, list, call, an unknown tool, an unknown method, and garbage input. |
| `test_tabs.py` | The Chrome tab tools against a made-up tab list: numbering, finding a tab by number or word, headless never touching Chrome, closing built only from parsed tab numbers, and the JavaScript-setting hint. |
| `test_memory.py` | Her memory across sessions against a temporary file: it survives a new session, repeats and blanks, ranked recall, careful forgetting, the 500 fact cap, a broken file, the harness asking first, and privacy from models and MCP. |
| `test_screen.py` | read_screen against a made-up OCR result: headless never captures, all lines or only matching ones, the Screen Recording hint, the temporary screenshot always removed, and privacy from models and MCP. |
| `test_documents.py` | Reading documents in a made-up folder under home: text, RTF through textutil, PDF through PDFKit, finding passages, and refusing hidden files, paths outside home, missing files, unknown types and empty files in words. |
| `test_reader.py` | Questions about documents and the screen with the reader model faked: a grounded answer comes back, an invented number or name is declined, UNKNOWN is declined, no Ollama falls back to passages, long text is narrowed to relevant passages, and the screen path stays private. |
| `eval/scorecard.py` | One line on how the repo stands: version, tools, tests, docs coverage, laws, the biggest Python file, and actions/parity/util_diff agreement. The loop appends it to docs/PROGRESS.md each round. |
| `test_llm.py` | ask_llm against fake local servers (no oMLX or Ollama needed): the default model, named models on either server, a missing model listing what is here, fallbacks, cut and empty answers, every error path, empty and over-long questions, the harness asking first, routing |
| `test_voice.py` | voice.py with fake ears and mouth: silence, phantoms and goodbyes sorted, questions answered and spoken, no microphone as a sentence; VOICE_LIVE=1 renders a question with `say` and checks the real Whisper hears it |
| `test_research.py` | tools_research.py with sources and writer stood in for: uncited, miscited and invented-number sentences dropped, only used sources listed, honest replies when nothing survives, routes, save_research to a default or named path, refused outside home |
| `test_write.py` | tools_write.py with the writer and home folder stood in for: drafts and saves under a slugged name, empty request refused, a blank or failed draft writes no file, "note" stays with new_note, it is a write |
| `test_see.py` | tools_see.py with the model and screenshot stood in for: the question reaches the model, files outside home or not pictures are refused, missing or broken models are sentences, the screenshot is removed, asked first, routes |
| `test_gui.py` | tools_gui.py with the screen reader and cliclick stood in for (no test ever clicks): box centers in points, exact match before contains, click, type and key commands, missing cliclick or an unreadable screen as a sentence, the harness asking before every step, routes |
| `test_screen_agent.py` | tools_screen_agent.py against a fake Ollama and fake screen tools (nothing real is ever clicked): a multi-step plan runs step by step, a no stops the whole job, she can look before acting, an unknown or broken tool is reported not raised, Ollama down is a sentence, the step cap is honest, and the four tools it may ever touch stay off the general model menu |
| `test_library.py` | library.py against a stand-in Wikipedia (no network): fetch, stubs skipped, exact titles, plurals, quotes, questions that name no page declined, no library yet, 429 backoff |

| `test_harness.py` | The harness keeps its promises: a no stops the write, a yes runs it once, reads never ask, the record is kept, and plan() runs nothing. |
| `eval/util_diff.py` | Runs about a hundred phrasings through tools_util.py and through its JavaScript twin in web/samantha.js under node, and fails on any difference in the words that come back. Also checks that near-miss sentences ("hash browns are good") are not stolen. |
| `eval/laws.py` | Checks the rules in LAWS.md against every tool, not a sample: side-effect tools are classified, hidden tools never reach a model or MCP, a no from the harness stops a write, her hands stay in the home folder, docs stay at 100 percent, Python and JavaScript agree, no em dashes. | `eval/a11y.py` | Audits the live landing page with axe-core (fetched at run time) in four modes, desktop and phone, light and dark, and fails on any WCAG 2 A or AA violation or best-practice issue. |
| `eval/smoke_images.py` | Runs all ten image tools for real through a hidden Pixelmator Pro on a sample photo and measures each output (size, rotation, saturation, transparency, difference from the original). | `web/paint.js` | Landing page painting demo. Shows live quadtree painting in the browser (three clickable paintings). |
| `scratch/` | Experimental from-scratch transformer (character-level, no pre-trained weights). Deliberately tiny, proves we can build one without repeating the Arthur gibberish failure. Not intended to be fluent. |
| `tui/` | Terminal UI. SwiftPM + SwiftTUI wrapper around the Python CLI. |
| `web/status.json` | Training progress (loss chart, phase tracker). Generated by `parse_log.py`, read by the landing page. |
| `web/index.html` | Landing page. Loss chart, training status, painter demo, project roadmap. |
| `wrangler.toml` | Cloudflare Worker deployment (landing page assets only). |
